# App language

Open **Settings** and find **Language**. On web and desktop, you can also search Settings for "language" or use the command palette's language setting entry.

Choose **English**, **简体中文** (Simplified Chinese), or **العربية** (Arabic) explicitly, or **System default** to follow this device when one of those languages is available. Arabic is available on web and desktop. Mobile does not offer it yet and stays in English or Simplified Chinese. An unsupported device language falls back to English. If the selected language cannot load, the app shows English and the Language setting says so, with **Try again** to load it again.

Arabic reads right to left. The whole interface mirrors: sidebars, menus, and arrows swap sides, and the change applies at once, with no restart. Your messages follow their own text, so an English reply stays left to right inside an Arabic interface and an Arabic reply reads right to left inside an English one, even within one message. Code, file paths, links, model names, and shortcuts always stay left to right. Numbers use Western digits and dates use the Gregorian calendar. The window buttons on macOS and Windows stay where your system puts them.

The choice stays on your client. It does not change the language preference on another browser, desktop installation, or mobile device connected to the same environment. Reset the language setting to return to the system default.

This setting controls interface copy only. Your messages, bot responses, bot names, instructions, code, and paths remain unchanged. It does not tell a bot which language to use when responding.

Translation is still in progress. Settings navigation and General settings, pairing, the command palette, connection status, the bot roster, chats, the composer, bot settings, memory, routines, and onboarding are translated. Dates and times in a chat follow your language. Some tools still show English, including the file browser, code-block diffs, and previews, as do the details inside most other Settings sections. Native desktop menus and startup dialogs also stay in English.

Memory and routine screens translate their labels only. Saved facts, memory notes, routine names, instructions, and run results stay as written.

Error explanations follow your language, but the original error text from a provider, git, or the environment stays as received so you can search for it or report it.
